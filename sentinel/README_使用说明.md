# 模型内部故障哨兵（真实小型LLM版）

给你电脑上的小型语言模型装一个"内脏体检仪"：不训练、不改模型、不要标注数据，
让模型读一遍正常文本顺带建好"正常状态档案"，之后随时可以体检——内部状态偏离
正常样子就报警，并指出坏在哪一层。

原理来自本项目论文《One Registry, Several Jobs》（paper2/ 目录），机制在 10 万
参数玩具模型上验证后，本包首次搬上真实的 8200 万参数预训练模型 distilgpt2。

## 一、安装（你的电脑，Windows/Mac/Linux 都行，纯 CPU）

需要 Python 3.9+。命令行里：

    pip install torch transformers

（第一次运行会自动从 HuggingFace 下载 distilgpt2 模型，约 350MB。）

## 一点五、最省事的试用（推荐先跑这个）

    python3 build_registry.py        # 先建档案（一次）
    python3 try_it.py                # 体检一段自带文本
    python3 try_it.py --break-layer 4  # 人为砍伤第4层，对比健康/损伤两种读数
    python3 try_it.py --file 你的英文文件.txt

**判定怎么工作（实测调过三轮才对）**：文本被切成 128 token 的块逐块读数，看
**多少比例的块落在正常范围之外**（健康模型约 16%，超过 30% 报警）。不要用一句话
体检——单条短文本方差极大，会误报；给它至少几百个词。

**两种异常会被区分开**：
- **只有一层报警** → 局部异常，疑似模型内部故障（实测：砍第4层 → 该层100%、另一层16%）
- **各层一起报警** → 全局异常，更可能是输入文本领域和档案不符（实测：健康模型喂法律
  英文 → 72%/56%），不是模型坏了

## 二、三个命令

    # 1. 建库（跑一次，约 2-5 分钟）：模型读自带的正常英文语料，建立正常状态档案
    python3 build_registry.py

    # 2. 体检（随时跑）：给任意一段英文，输出每层健康读数和结论
    python3 check_health.py --text "Any English text you want to run through."

    # 3. 眼见为实的演示：先看健康模型的读数，再人为损伤模型第4层，看它报警并指认第4层
    python3 demo_faults.py

## 三、在真实模型上的实测成绩（本包发布前测的，240 异常 vs 240 正常序列）

报警准确率（AUC）：0.5 = 瞎猜，1.0 = 完美。两个读数通道取更好的那个：

| 内部故障类型 | 报警准确率 |
|---|---|
| 随机砍掉 30% 活跃单元 | **0.94** |
| 30% 单元永久卡死（硬件坏道式） | **1.00** |
| 等幅高斯噪声 | 0.58（弱项，如实说） |
| 4级粗量化失真 | 0.68（弱项，如实说） |

定位能力（故障打在哪层，哪层的检测器最响）：

| | 第2层检测器 | 第4层检测器 |
|---|---|---|
| 故障在第2层 | **0.92** | 0.53（下游几乎无感） |
| 故障在第4层 | 0.50（上游恰好安静） | **0.94** |

"上游安静 = 病灶在下游"这个定位签名，在真实模型上比玩具模型还干净。

## 四、诚实的边界（用之前必读）

0. **已实测的一个漏报，必须知道**：让第4层 10% 的单元永久卡死，对模型输出的
   伤害（loss +0.034）和"砍掉30%活跃单元"（+0.042）**差不多**，但哨兵抓到后者
   （100%异常块）却漏掉前者（25%，没过线）。原因是机制只看"哪些单元处于高激活"
   ——被卡死的若本来就不在高激活集合里，读数就看不见它，哪怕模型确实变差了。
   **所以：报警了基本可信，没报警不等于模型没事。**
1. **强项是"改变了高激活模式"的损伤**（活跃单元被清零、粗量化），
   报警准确率 0.94-1.00。**弱项是数值级失真**（高斯噪声等），真实模型上
   只有 0.55-0.68，比玩具模型差——原因初步判断与真实模型激活值的离群值
   分布有关，尚未深入排查。
2. 它检测的是**模型内部**出问题；判断**输入文本**怪不怪，用模型自己的
   困惑度更好，不要拿它抢这个活。
3. 档案是在自带的技术英文语料上建的。你如果拿它体检的文本领域差很远
   （比如诗歌、代码），"正常范围"会偏，建议用你自己领域的正常文本重建库：
   `python3 build_registry.py --corpus 你的文本.txt`
4. 只在 distilgpt2（82M）上验证过。换别的 GPT-2 家族模型大概率能直接跑
   （`--model gpt2` 等）；换架构（Llama 类）需要小改 sentinel.py 里定位
   激活模块的函数。
5. 登记库文件约 100MB（建库时本地生成），没随包附带。

## 五、文件清单

    sentinel.py          核心：登记器挂载、两通道读数、体检报告
    registry.py          共激活组登记器（与论文完全同一份代码，8/8单元测试）
    build_registry.py    命令1：建库
    check_health.py      命令2：体检
    demo_faults.py       命令3：故障演示
    default_corpus.txt   自带正常语料（4MB 技术英文）
    validate_results.json 发布前在真实模型上的完整实测数字
